Decode.IC — Phase 3 Changelog
==============================
(Real-data wiring for Dependencies, Risk Center, Technical Debt,
Code Health, Reports — mock data removed for these pages only)

1. PHASE 3 COMPLETED FEATURES
------------------------------
- Dependencies page now shows real detected dependencies from the
  analyzed repository's manifest files (package.json, requirements.txt,
  etc.), not the mock react/next/prisma list.
- Risk Center now shows real risks derived from the analyzer's
  deterministic findings (hardcoded secrets, eval usage, deep nesting,
  large files, TODO/FIXME, large API surface, etc.), not the mock
  auth-service/billing-service risks.
- Technical Debt now shows real findings grouped by category, plus
  the analyzer's actual technicalDebtPercent, not the mock issue list.
- Code Health now displays the real healthScore, linesOfCode, and
  languages from the repository's stored analysis (reuses the existing
  GET /api/repositories/:id endpoint — no new endpoint needed).
- Reports now assembles report summaries live from the current
  repository.analysis object (health, architecture, risk, technical
  debt, dependencies) instead of a mock report list. No fake report
  history is presented — reports reflect only the current analysis,
  since no report persistence exists in this project.
- Settings required no changes: its repository-related fields were
  already static UI, not bound to mock data.

4. NEW API ENDPOINTS
-----------------------
GET /api/repositories/:id/dependencies
GET /api/repositories/:id/risks
GET /api/repositories/:id/technical-debt
GET /api/repositories/:id/reports

All four:
- validate the repository id (400 if invalid)
- 404 if the repository doesn't exist
- 404 with a clear message if the repository hasn't been analyzed yet
- read only from the existing repository.analysis object
- never call GitHub or touch MongoDB directly

Existing endpoint reused (no new endpoint needed):
GET /api/repositories/:id  — now also the real data source for Code Health

6. KNOWN LIMITATIONS
------------------------
- Repository + analysis state is stored in memory only
  (server/services/repository.service.js), not MongoDB. A server
  restart clears all connected repositories and their analysis
  results. MongoDB is currently only used for authentication
  (server/models/User.js). This predates Phase 3 and was not
  introduced or fixed by it.
- Reports have no history/persistence — the Reports page always
  reflects the *current* analysis, not past analyses over time.
- Technical Debt has no fixed category taxonomy (complexity/
  duplication/coupling/etc.) — categories come directly from
  whatever the analyzer's rule findings report, which may not match
  the old mock UI's categories 1:1.
- Code Explorer, AI Assistant, Impact Analysis, Change Simulation,
  and Refactoring are still fully mocked — planned for Phase 4/5.
  Code Explorer in particular needs a backend gap filled first: the
  analyzer currently only produces aggregate counts, not a persisted
  per-file path/language/LOC list.
- node_modules is NOT included in this zip (both root and server/) —
  run `npm install` in both folders before running. The node_modules
  originally bundled in the uploaded project contained platform-
  specific native binaries (Rollup) that do not run cross-platform;
  a fresh install avoids this entirely.
- dist/ (a stale Vite build output folder) and tsconfig.tsbuildinfo
  (a build cache file) are excluded as build artifacts, not source.
